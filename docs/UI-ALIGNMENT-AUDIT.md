# UI 정렬 점검 (UI Alignment Audit) — 2026-06-19

전체 페이지를 Chrome(claude-in-chrome MCP)으로 모바일 폭(약 526px)에서 캡처하고,
각 화면의 버튼·텍스트·아이콘 정렬을 소스(Tailwind 클래스)와 대조하여 점검했다.

## 점검 범위 (캡처한 화면)

| 경로 | 화면 | 정렬 상태 |
| --- | --- | --- |
| `/login` | 로그인 | OK |
| `/` | 홈(피드) | OK (하단 탭바 아이콘만 보정) |
| `/search` | 커뮤니티 검색 | OK |
| `/me` | 프로필 | OK |
| `/c/:slug` | 커뮤니티 상세 | OK |
| `/c/:slug/create-post` · `/create-post` | 글 작성 | OK |
| `/create-community` | 커뮤니티 만들기 | OK |
| `/p/:postId` | 스레드(채팅) | 헤더 제목 비대칭 → 수정 |

대부분의 화면은 일관된 Tailwind 유틸리티(`flex items-center`, `justify-*`, `min-h-[44px]`)로
정렬이 잘 맞아 있다. 아래 3건만 실제 정렬 어긋남으로 확인되어 수정한다.

## 발견된 정렬 문제 및 수정안

### 1. 스레드 헤더 제목이 가운데 정렬되지 않음 (확실한 결함)

- **파일**: `frontend/src/pages/Thread.tsx` (`<header>`, 약 317–350행)
- **현상**: 헤더는 `flex items-center` 구조로 `[뒤로 버튼] · [제목(flex-1, text-center)] · [북마크][메뉴]` 배치다.
  왼쪽은 버튼 1개(약 36px), 오른쪽은 버튼 2개(약 80px)라 좌우 폭이 비대칭이다.
  `flex-1` 영역이 한쪽으로 밀려, `text-center` 제목이 헤더의 실제 중앙보다 **왼쪽으로 치우쳐** 보인다.
- **수정**: 제목 왼쪽에 오른쪽 버튼 1개 폭만큼의 **투명 스페이서**(`h-9 w-9 shrink-0`)를 추가해
  좌우 클러스터 폭을 맞춘다 → 제목이 헤더 정중앙에 위치.

### 2. 하단 탭바 이모지 아이콘의 수직 정렬 불균일

- **파일**: `frontend/src/layout/BottomTabBar.tsx`
- **현상**: 🏠/🔍/✏️/👤 이모지가 `text-lg leading-none`으로만 렌더되어, 글리프마다
  베이스라인이 달라 아이콘이 미세하게 위아래로 들쭉날쭉하다.
- **수정**: 각 아이콘을 **고정 높이의 flex 중앙 정렬 박스**(`flex h-6 items-center justify-center`)로 감싸
  4개 아이콘이 동일한 수직 중심선을 공유하도록 한다(라벨 baseline도 균일해짐).

### 3. Composer 첨부(＋)·전송(↑) 버튼 크기 불일치

- **파일**: `frontend/src/components/Composer.tsx`
- **현상**: 첨부 버튼은 `h-9 w-9`(36px), 전송 버튼은 `h-11 w-11`(44px)로 크기가 다르다.
  입력 행이 `items-end`라 작은 첨부 버튼이 바닥에 붙으면서 ＋ 아이콘이 ↑ 아이콘보다 낮게 보인다.
- **수정**: 첨부 버튼을 전송 버튼과 동일한 `h-11 w-11`로 맞춰 두 아이콘 중심선을 일치시킨다.

## 수정하지 않은 항목 (의도된 디자인)

- **채팅 버블의 아바타 하단 정렬**(`items-end`): 일반적인 채팅 UI 패턴으로 의도된 배치.
- **버블 작성자/시간 라벨의 `px-1` 들여쓰기**: 버블 본문(`px-3`) 대비 의도적 미세 들여쓰기.
- **이모지 자체의 글리프 편차**: OS·폰트에 종속되는 부분으로, 정렬 박스(#2)로 흡수 가능한 범위만 보정.

## 2차 점검 — 데스크톱 뷰(>=1024px) 스레드 화면 (2026-06-19)

1차는 모바일 폭(약 526px)에서 점검했으나, 데스크톱 뷰(사이드바 노출, 너비 ≥1024px)에서
스레드(`/p/:postId`) 화면에 추가 정렬·레이아웃 문제 4건이 확인되어 보정한다.
모두 데스크톱 폭(innerWidth ≈ 1587)에서 Chrome MCP로 재현·확인했다.

### 4. 뒤로가기 버튼이 제목과 세로 가운데 정렬되지 않고, 아이콘이 너무 작음

- **파일**: `frontend/src/pages/Thread.tsx` (헤더)
- **현상**: 뒤로가기 버튼이 `‹`(U+2039) **텍스트 글리프**라 글리프 자체 베이스라인이
  높게 렌더되어, 버튼 박스는 `items-center`여도 보이는 화살표가 제목 중심선보다 위로 뜬다.
  또한 글리프가 가늘고 작아 시각적으로 빈약하다.
- **수정**: `‹` 글리프를 **SVG chevron 아이콘**(`h-6 w-6`, stroke 2.5)으로 교체하고
  버튼 박스를 `h-10 w-10`로 키운다 → flex 중앙 정렬로 제목과 정확히 세로 중앙 일치 + 충분한 크기.

### 5. 헤더 제목이 정확히 가운데 정렬되지 않음 (구조 개선)

- **파일**: `frontend/src/pages/Thread.tsx` (헤더)
- **현상**: 1차에서 투명 스페이서로 좌우 폭을 맞췄으나, 버튼 크기가 달라지면 다시 틀어지는
  취약한 구조였다.
- **수정**: 헤더를 `[좌측 그룹 flex-1][제목][우측 그룹 flex-1]` 3분할로 바꿔, 좌/우 그룹이
  동일 폭으로 늘어나 제목이 **버튼 크기와 무관하게 항상 정중앙**에 오도록 한다(스페이서 제거).

### 6. 댓글 작성 섹션(Composer)이 화면에 다 들어오지 않고 하단이 잘림

- **파일**: `frontend/src/pages/Thread.tsx` (루트 컨테이너 높이)
- **현상**: 데스크톱에서 스레드 높이가 `h-[calc(100dvh-3rem)]`(헤더만 차감)인데,
  `<main>`의 데스크톱 패딩(`pt-4`=1rem + `pb-8`=2rem)은 차감하지 않아
  총 높이가 뷰포트를 약 3rem 초과 → Composer 하단이 잘린다.
- **수정**: 데스크톱 높이를 `desktop:h-[calc(100dvh-6rem)]`로 변경
  (헤더 3rem + main 상하 패딩 3rem 차감). 모바일/태블릿은 음수 마진으로 이미 보정되어 영향 없음.

### 7. Composer의 + 버튼이 입력 박스와 세로 가운데 정렬 안 됨

- **파일**: `frontend/src/components/Composer.tsx` (입력 행)
- **현상**: 입력 행이 `items-end`라 작은 버튼(44px)이 더 높은 입력 박스 하단에 붙어
  ＋ 아이콘이 박스 중심보다 아래로 내려간다.
- **수정**: 입력 행을 `items-center`로 변경 → ＋·입력 박스·전송(↑) 버튼 중심선 일치.

### 8. "메시지를 입력하세요…" 박스 안 텍스트가 세로 가운데 정렬 안 됨

- **파일**: `frontend/src/components/Composer.tsx` (textarea)
- **현상**: textarea에 `min-h-[42px]`가 걸려 한 줄 텍스트보다 박스가 커지고,
  textarea 텍스트는 상단 정렬이라 빈 공간이 아래로 몰려 텍스트가 위로 치우친다.
- **수정**: textarea의 `min-h-[42px]` 제거 → 한 줄 높이가 되어 래퍼의 `items-center`로
  텍스트가 박스 세로 중앙에 위치(여러 줄 입력 시 `max-h-28`까지 정상 확장).

## 3차 점검 — 채팅 버블 한 줄 텍스트 아래 공백 (2026-06-19)

### 9. 댓글(채팅) 버블에서 한 줄 텍스트 아래에 큰 공백이 생김

- **파일**: `frontend/src/lib/sanitize.ts` (`renderMarkdownSafe`)
- **요청 분석**: 스레드의 채팅 버블("저는 아침 루틴을 추천해요! 😊" 등)에서 한 줄짜리
  텍스트인데도 버블 하단에 한 줄 높이(약 23px)의 큰 빈 공간이 보인다.
- **원인 (DOM 실측으로 확정)**:
  - `marked.parse()`는 단락을 `<p>…</p>\n` 형태로 출력한다 — `</p>` **뒤에 개행 문자(`\n`)**가 붙는다.
  - 채팅 버블의 마크다운 래퍼(`ChatBubble.tsx` / `SummaryBubble.tsx`)에는 `whitespace-pre-wrap`이
    적용되어 있어, 이 꼬리 `\n`이 **눈에 보이는 빈 줄 한 칸**으로 렌더된다.
  - 실측: 래퍼 높이 46px = 본문 `<p>` 23px + 꼬리 `\n` 23px → 버블이 불필요하게 62px로 커짐.
  - 참고: marked 옵션이 `breaks: true`라 사용자 줄바꿈은 이미 `<br>`로 변환되므로,
    줄바꿈 보존을 위해 `whitespace-pre-wrap`이 꼭 필요한 것은 아니다. 꼬리 `\n`은 순수 포맷 부산물.
- **수정**: `renderMarkdownSafe`의 반환 HTML을 `.trim()` 하여 선행/후행 공백(꼬리 `\n`)을 제거한다.
  중앙 chokepoint 한 곳만 고치므로 모든 SafeMarkdown 사용처(버블·요약·원본글 본문)에 일관 적용된다.
  콘텐츠 태그(`<p>` 등) 바깥의 장식용 공백만 제거되어 보안·렌더 의미 변화는 없다.
- **결과**: 버블 높이 62px → 약 44px(min-h-[44px] 기준)로, 한 줄 아래 빈 줄이 사라진다.
