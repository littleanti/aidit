> **여러 사람이 하나의 AI 컨텍스트를 공유하며 협업하는 Reddit형 커뮤니티 모바일 웹**

## 1. 배경 & 영감 (agent-cli)

본 제품은 오픈소스 [`dujeonglee/agent-cli`](https://github.com/dujeonglee/agent-cli)에서 영감을 받았다.
조사 결과 agent-cli의 핵심 가치는 **"여러 뷰어가 하나의 살아있는 AI 세션을 공유하며 동시에 개입(steer)한다"** 는 fan-out 모델과,
**컨텍스트가 한도에 차면 자동으로 오래된 대화를 요약·압축하는 엔진**(`agent_cli/context/manager.py`, 90% 임계치 요약)에 있다.

다만 agent-cli는 **단일 세션·단일 프로세스·서버 보관 API 키·계정 없음(임시 닉네임)·파일(JSONL) 저장**구조라
Reddit형 멀티테넌트 커뮤니티에는 그대로 쓸 수 없다. 따라서 Aidit은:

- agent-cli를 **개념적 레퍼런스 + 요약 엔진 패턴 출처**로 삼고,
- **새로운 경량 멀티테넌트 백엔드**를 구축하며,
- 요약/컨텍스트 압축 로직은 `manager.py`의 아이디어를 **클라이언트(브라우저) TypeScript로 포팅**한다.

> 라이선스: **MIT** (Aidit는 MIT 기준으로 진행).

## 2. 제품 한 줄 정의

**Aidit** = 글마다 "채팅방형 댓글 스레드"가 열리고, 그 안에서 **여러 사용자가 하나의 AI 컨텍스트를 함께 쌓아가며**
커뮤니티별 페르소나를 가진 AI와 협업하는 커뮤니티. **AI 추론 비용·키는 전적으로 사용자 본인(BYOK, Google Gemini)이 부담**한다.

---

## 3. 핵심 차별점 (Why Aidit)

1. **공유 AI 컨텍스트** — Reddit의 트리형 댓글이 아니라, 하나의 글 스레드가 곧 하나의 누적 대화. 모두의 댓글이 같은 컨텍스트를 형성하고, `@AI`는 그 누적 위에서 답한다.
2. **커뮤니티별 AI 페르소나** — 같은 질문도 커뮤니티(=페르소나)에 따라 다른 톤·전문성으로 답한다.
3. **BYOK (Bring Your Own Key)** — 서버는 LLM 키를 보유/대납하지 않는다. 각자 자신의 Gemini 키로 직접 Google에 호출하고, 결과만 서버에 게시한다. → 서버 비용 최소화, 키 노출 면적 최소화.
4. **무한 대화의 자동 요약** — 누적 컨텍스트가 128K 토큰을 넘으면 AI 요약 버블(색상 구분)이 자동 삽입되어 스레드가 영원히 이어질 수 있다.

## 4. 대상 사용자 & 페르소나

| 페르소나 | 설명 | 핵심 니즈 |
|---------|------|----------|
| **작성자(Poster)** | 질문/주제를 던지는 사람 | 즉시 AI 1차 답변 + 사람들의 후속 토론 |
| **참여자(Commenter)** | 스레드에 참여하는 사람 | 채팅하듯 가볍게 의견 + 필요 시 `@AI` 호출 |
| **커뮤니티 생성자(Creator)** | 커뮤니티를 만들고 페르소나를 정의 | 자기 주제의 AI 톤·전문성 큐레이션 |
| **탐색자(Browser)** | 인기글/커뮤니티를 둘러보는 사람 | 홈 인기 피드 + 커뮤니티 검색 |

전제: PoC 단계 사용자는 **자신의 Google AI Studio API 키를 발급받을 수 있는** 기술 친화적 얼리어답터.

## 5. 범위 (Scope)

### 5.1 In Scope (PoC)
- 사용자 식별: **username + password 로그인** → 서버 JWT 토큰 발급 (토큰만 로컬 스토리지 저장, 비밀번호는 미전송). **Google AI Studio API 키**는 로컬 스토리지 저장, 서버 미전송(BYOK).
- 커뮤니티: **사용자 생성**(이름 + AI 페르소나 프롬프트), 생성자가 페르소나 소유/편집.
- 글 작성/조회, 인기 홈 피드, 커뮤니티 검색.
- 글 작성 시 **자동 1차 AI 답변 버블**(작성자 키로 호출).
- 채팅방형 댓글 스레드 (좌: 타인+AI, 우: 본인).
- `@AI` 멘션 → 호출자 키로 AI 답변 버블 생성.
- 128K 초과 시 **AI 요약 버블** 자동 생성(다른 색), 이후 요약 기반 컨텍스트로 전환.
- 스레드 실시간 갱신(다중 사용자 동시 시청).
- LLM: **Google Gemini Flash Lite 계열만** 지원(PoC).

### 5.2 Out of Scope (PoC 이후)
- OAuth/이메일 인증, 계정 복구, 비밀번호 변경/리셋.
- 비-Google LLM(OpenAI/Anthropic 등), 서버 대납 키.
- 업/다운보트 알고리즘 정교화, 카르마, 모더레이션 도구, 신고/차단.
- 이미지/파일 첨부, 리치 미디어, 스레드 검색(전문 검색).
- 모바일 네이티브 앱(웹/PWA만), 푸시 알림.
- 다국어 i18n(한국어/영어 혼용 카피만).

## 6. 기능 요구사항 (FR)

원 요청의 7개 동작을 추적 가능한 FR로 분해한다.

### FR-1 홈 / 탐색
- **FR-1.1** 홈 화면에 **최근 인기 게시글** 피드(카드 리스트)를 노출한다. 인기 점수 = f(추천 수, 댓글 수, 최신성). PoC 공식은 TRD 참조.
- **FR-1.2** **커뮤니티 검색** 기능 제공(데스크톱: 우측 패널, 모바일: 상단 검색 진입). 이름/설명 부분일치.
- **FR-1.3** 미로그인 상태에서도 홈/글 열람 가능(읽기 전용). 작성·`@AI`·요약 등 쓰기/AI 동작은 로그인 필요.

### FR-2 인증 / 식별
- **FR-2.1** 로그인 시 `username` + `password` 입력 → 서버가 JWT 토큰 발급. 회원가입(username 중복 차단) + 첫 로그인. **localStorage에 토큰 저장.**
- **FR-2.2** API 키는 **서버로 전송되지 않으며**, Aidit 서버 DB에 저장되지 않는다(브라우저 → Google 직접 호출).
- **FR-2.3** username은 게시 시 작성자 표시·본인 댓글(우측 버블) 판별에 사용된다. **서버는 JWT 토큰을 검증해 요청 사용자를 식별**(x-user-id 신뢰 폐기).
- **FR-2.4** 로그아웃 시 localStorage의 토큰을 제거한다.

### FR-3 커뮤니티
- **FR-3.1** 로그인 사용자는 **커뮤니티를 생성**할 수 있다: 이름(고유 slug), 설명, **AI 페르소나 프롬프트**.
- **FR-3.2** 페르소나 프롬프트는 해당 커뮤니티 모든 AI 호출(1차 답변, `@AI` 답변, 요약)의 system instruction 기반이 된다.
- **FR-3.3** 생성자는 자신이 만든 커뮤니티의 페르소나를 편집할 수 있다.

### FR-4 게시글
- **FR-4.1** 작성자는 특정 커뮤니티에 글(제목+본문)을 작성한다.
- **FR-4.2** 게시 즉시 글이 서버에 **먼저 등록**되고 스레드 화면으로 진입한다.
- **FR-4.3 (요청 #3)** 글 게시 직후, **작성자 본인 키로** 커뮤니티 페르소나 기반 **1차 AI 답변 버블**을 생성한다. 호출 중에는 **로딩(타이핑) 표시**, 응답 도착 시 좌측 AI 버블로 등록.
- **FR-4.4** 작성자는 자신이 작성한 글을 조회 후 **제목·본문·이미지를 편집**할 수 있다. 스레드 헤더의 **[편집] 버튼**으로 편집 폼에 진입, 기존 값 프리필 후 수정·저장. 비작성자에게는 [편집] 버튼 미표시.

### FR-5 댓글 스레드(채팅방형)
- **FR-5.1 (요청 #4)** 스레드 상단에 **글 원본** 고정, 하단은 **채팅방형 버블 리스트**.
- **FR-5.2** **타인 댓글 + 모든 AI 버블 = 좌측 버블**, **본인 댓글 = 우측 버블**.
- **FR-5.3** 버블은 작성자명/시간/타입(사람/AI/요약)을 표시. AI·요약 버블은 시각적으로 구분.
- **FR-5.4** 다중 사용자가 같은 스레드를 동시에 볼 때, 새 버블이 **실시간으로** 모두에게 반영된다.

### FR-5.5 북마크
- **FR-5.5a** 로그인 사용자는 Thread 헤더의 **🔖 북마크** 버튼으로 글을 북마크할 수 있다. 낙관적 토글(즉시 UI 반영), 서버 `POST /posts/:id/bookmark`(idempotent upsert) 호출. 실패 시 상태 롤백.
- **FR-5.5b** 북마크를 해제하려면 버튼을 다시 클릭. 서버 `DELETE /posts/:id/bookmark`(idempotent delete) 호출.
- **FR-5.5c** 로그아웃 상태에서 북마크 시도 시 로그인 모달을 띄운다.
- **FR-5.5d** 프로필 화면(👤 나)에 **"북마크한 글" 섹션**을 추가. 해당 사용자가 북마크한 글 목록(최신 북마크순)을 피드 카드로 노출. 빈상태: "북마크한 글이 없어요".

### FR-6 @AI 멘션
- **FR-6.1 (요청 #5)** 댓글에 `@AI` 태그를 포함해 등록하면, AI가 **(현 컨텍스트 = 글 원본 + 기존 AI 버블 + 기존 사람 버블)** 을 기반으로, **해당 `@AI` 댓글에 대한** 신규 AI 답변 버블을 생성한다.
- **FR-6.2** AI 호출은 **`@AI`를 단 사용자 본인 키**로 수행한다. 사람 댓글이 **먼저 등록**되고, AI 답변은 **로딩 표시 후** 도착 시 등록(요청 본문의 "우선 등록 → 로딩 → 등록" 순서).
- **FR-6.3** `@AI`가 없는 일반 댓글은 단순 게시(즉시 등록, AI 호출 없음).

### FR-7 컨텍스트 자동 요약 (128K)
- **FR-7.1 (요청 #6)** 누적된 **활성 컨텍스트**의 토큰 수가 **128K를 초과**하면, 지금까지 내용을 요약한 **AI 요약 버블(색상 구분)** 을 스레드에 삽입한다.
- **FR-7.2 (요청 #7)** 요약 버블 생성 **이후**의 `@AI` 댓글은, **(가장 최근 AI 요약 버블 + 그 이후의 모든 버블)** 만을 컨텍스트로 사용해 답변한다. (요약 이전 원본/히스토리는 컨텍스트에서 제외)
- **FR-7.3** 요약 트리거 시점/실행 키 정책(설계 결정): **다음 `@AI` 호출자**의 키로 **지연(lazy) 실행**한다. 즉, `@AI` 처리 직전에 활성 컨텍스트가 128K를 넘으면 → 먼저 요약 버블 생성·게시 → 그 다음 (요약 기준) 답변 생성. (근거: BYOK라 서버에 키가 없어 매 버블마다 즉시 요약 불가. TRD §6 참조.)
- **FR-7.4** 요약 버블은 사람 댓글이 아니므로 좌측·구분 색(예: 보라/앰버)으로 표시되고, "여기까지 요약됨" 경계 의미를 시각적으로 전달한다.

### FR-8 Gemini 연결 표식 (헤더 배지)
- **FR-8.1** 로그인 상태에서 상단바 아이디(`[ {username} ]`) **바로 좌측**에 Gemini 연결 상태 표식(LED 점 + `GEMINI` 라벨, 레트로 인광 스타일)을 표시한다.
- **FR-8.2** 상태 판정은 **가장 최근 실제 LLM 쿼리**(브라우저→Gemini `generateContent`) 결과를 따른다: 최근 쿼리 성공 → **연결됨**(초록), 최근 쿼리 실패 → **끊김**(빨강), 아직 호출 없음 → **미확인**(흐림). hover 시 한국어 설명 툴팁.
- **FR-8.3** 표식은 세션-한정 신호다(서버 영속 없음). 하드 리로드 시 "미확인"으로 초기화되어, 실제로 관측된 결과만 표시한다.
- **FR-8.4** 로그인(또는 키 설정/변경) 시 **키당 1회 가벼운 연결 테스트**를 수행해, 첫 `@AI` 호출 전에도 배지가 즉시 연결/끊김을 반영한다. 테스트는 생성 비용이 없는 토큰 카운트 호출로 키·네트워크만 검증한다.

### FR-9 추천(업보트)
- **FR-9.1** 로그인 사용자는 글의 **▲ 점수 버튼**으로 추천할 수 있다. 사용자당 글당 1표(`Vote` 멱등). 다시 누르면 추천 취소(토글). 글 점수(`score`)는 추천 수를 반영하며 인기 정렬(hotScore)에 반영된다.
- **FR-9.2** ▲ 버튼은 **피드 카드(PostCard)와 글 상세(Thread) 양쪽**에서 동작하며, 낙관적 토글(즉시 UI 반영) 후 서버 점수로 동기화, 실패 시 롤백한다.
- **FR-9.3** 내가 추천한 글은 강조 색으로 표시되고, 이 상태는 재로드 후에도 유지된다(서버가 `voted`를 계산해 응답).
- **FR-9.4** 로그아웃 상태에서 추천 시도 시 로그인 모달을 띄운다.

## 7. 핵심 사용자 흐름 (User Journeys)

### J1. 첫 방문 → 글 작성 → 1차 AI 답변
1. 홈에서 인기글/커뮤니티 탐색 → 로그인(username+키) →
2. 커뮤니티 선택 → "글쓰기" → 제목/본문 작성 → 게시(서버 먼저 등록) →
3. 스레드 진입, 상단 원본 노출 → 작성자 키로 1차 AI 답변 로딩 → AI 좌측 버블 등록.

### J2. 협업 토론 + @AI
1. 다른 사용자가 스레드 입장(실시간) → 우측에 본인 댓글 작성 →
2. 누군가 `@AI ...` 댓글 → 본인 댓글 우측 즉시 등록 → AI 로딩 → AI 좌측 버블 등록(모두에게 실시간).

### J3. 장기 스레드 → 자동 요약
1. 토론이 길어져 활성 컨텍스트가 128K 근접 →
2. 다음 `@AI` 호출 시, 호출자 키로 **요약 버블** 먼저 생성(색 구분) →
3. 이후 `@AI`는 요약 + 이후 버블만 보고 답변. 스레드는 계속 이어짐.

## 9. 비기능 요구사항 (NFR)

- **NFR-1 모바일 우선**: 360–430px 폭 최적화, PWA 설치 가능(선택), 터치 타깃 ≥ 44px.
- **NFR-2 보안/프라이버시**: API 키는 클라이언트에만 존재. 서버 로그/응답에 키가 포함되지 않음. XSS 방지(키 탈취 표면) — TRD §8.
- **NFR-3 성능**: 홈 피드 LCP < 2.5s(3G Fast 기준), 스레드 초기 50버블 페이지네이션.
- **NFR-4 가용성**: 서버 무상태(stateless) 위주, 수평 확장 가능 구조(SSE 세션은 sticky 또는 pub/sub).
- **NFR-5 신뢰성**: AI 호출 실패 시 사람 댓글은 보존되고 AI 버블만 "실패/재시도" 상태로 표시.
- **NFR-6 비용**: 서버는 LLM 비용 0(전부 BYOK). 인프라는 CRUD+SSE 수준.

## 10. 가정 & 의존성 (Assumptions)

- **A-1** PoC LLM 모델 ID는 **`gemini-3.1-flash-lite`** 로 고정한다. (TRD §5)
- **A-2** 128K는 **활성 컨텍스트 세그먼트**(마지막 요약 이후 누적) 기준이며, Gemini 모델 한도와 별개의 **제품 정책 임계치**다.
- **A-3** username은 표시·본인 판별용 식별자. PoC에서는 약한 고유성(선점/중복 허용 여부는 TRD에서 결정).
- **A-4** 토큰 카운팅은 클라이언트에서 추정(휴리스틱) 또는 Gemini `countTokens` 사용. 버블별 토큰 수를 저장해 합산.
- **A-5** 동시 `@AI`/동시 요약 같은 경쟁 상태는 PoC에서 서버 정렬·간단한 멱등 키로 단순 처리(완전한 분산 합의는 비범위).
